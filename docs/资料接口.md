# 资料服务接口

本地来源保留独立会话的邮件编号及 DELE 标记；只有 QUIT 更新共享邮箱，RSET 清除本会话标记。切换发布日期后 CAPA 不再包含 UIDL，UIDL 返回 -ERR。

本地网关将 POP3 命令分别映射为 /session/<会话>/capa、uidl、retr/<编号>、top/<编号>，返回的是未改写的命令应答。dele、rset、quit 使用 POST，语义仍按 POP3 会话处理。样例均为虚构邮箱，不发送真实邮件。UIDL 身份仅在对应邮箱内有效，Message-ID 不保证存在或唯一。

本地服务的资料入口为 `/session/1/retr/1`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期；`fixtures/handoff.json` 提供两封同主题同日期、不同正文的邮件及断连场景，用于正式收件与清理交接。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置；阶段级 `faults` 可对指定命令配置 `before-commit`（应答前断连且来源端不生效）与 `after-commit`（来源端先更新再断连、应答丢失），不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。

## 正式收件与清理交接

清理来源端邮箱分四个动作，结论只来自完整原件与新会话核对，不来自“上一次发过什么命令”。

1. 正式收件（RETR）：只接受完整 POP3 多行应答，抽取信封内完整邮件字节并写入原件目录；TOP 只返回部分正文，能预览但永远不能作为收妥依据。没有本地完整原件留存的邮件，系统拒绝发送 DELE。
2. 标记删除（DELE）：编号仅在当前来源会话内有效，标记只改本会话状态，邮箱在 QUIT 前不会更新；重复标记同一封会被拒绝。
3. 提交（QUIT）：QUIT 是来源端唯一更新点。收到明确应答仍记为 `acknowledged-unverified`；应答前断连记为 `quit-ambiguous`，禁止推测是否生效。
4. 新会话核对（reconcile）：下一班开新会话扫描邮箱当前实际内容，确认不存在才转为 `deleted-confirmed`——这是唯一可视为“已清掉”的状态；仍存在则为 `still-present`，曾确认删除又出现为 `present-again`。核对不重发删除命令，不需要再清空一次邮箱。

清理状态机：`retained → marked → acknowledged-unverified → deleted-confirmed` 是正常路径；断连分支为 `marked-ambiguous` 与 `quit-ambiguous`，均通过新会话核对收敛；`still-present` 可在留存依据仍有效时重新走标记流程。

## 身份依据与无法保证之处

- UIDL 可用：身份依据为 UIDL（`basis: "uidl"`），仅在该邮箱内有效，邮箱重建后可能失效；编号不写入长期身份。
- UIDL 不可用：身份依据降级为完整原件的 SHA-256 摘要（`basis: "content"`）。它能确认本地留存与来源内容一致，但内容完全相同的不同邮件无法区分；主题、日期、Message-ID 只作参考字段，不参与合并判断，同主题同日期的两封邮件始终是两条独立记录。
- 能力降级（UIDL 邮箱变为不支持 UIDL）时的跨能力核对结果记为 `unverifiable-capability-change`，保持原状态并写明原因。
- 每条记录的 `warnings` 显式列出该身份无法保证的地方；交接摘要（`GET /maildrop/handoff`）只列待办，已确认删除不计入待办。
