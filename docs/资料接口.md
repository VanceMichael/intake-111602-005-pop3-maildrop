# 资料服务接口

本地来源保留独立会话的邮件编号及 DELE 标记；只有 QUIT 更新共享邮箱，RSET 清除本会话标记。切换发布日期后 CAPA 不再包含 UIDL，UIDL 返回 -ERR。无 UIDL 时改用 LIST 取得本会话编号与大小，编号在下次连接不保证稳定。

本地网关将 POP3 命令分别映射为 /session/<会话>/capa、uidl、list、retr/<编号>、top/<编号>，返回的是未改写的命令应答。dele、rset、quit 使用 POST，语义仍按 POP3 会话处理。样例均为虚构邮箱，不发送真实邮件。UIDL 身份仅在对应邮箱内有效，Message-ID 不保证存在或唯一。

本地服务的资料入口为 `/session/1/retr/1`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期；`fixtures/purge.json` 用于收件与清理场景，协议应答全部动态生成。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。另有场景控制：`seed` 注入测试邮件（随后 RETR/TOP/LIST 动态生成，未注入时回落静态 fixture），`flaky-quit` 让下一次 QUIT 已更新邮箱但不返回应答，`drop-quit` 让下一次 QUIT 在处理前断开（删除不提交），`truncate-retr` 让下一次 RETR 传输中断。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

## 正式收件与清理语义

- TOP 与被截断的 RETR 只能预览，不产生收件凭据；只有以 `CRLF.CRLF` 完整收尾、通过校验并写入原件目录的 RETR 才算收妥。
- 会话编号只在当前会话内有效；DELE 只是本会话标记，QUIT 应答前来源端不更新。
- QUIT 有三种结果：`acknowledged`（收到 +OK，确定进入更新）、`ambiguous`（连接静默断开，无法区分退出前断开还是应答丢失，禁止按已发命令推断）、以及其它命令的 `disconnect`（退出前断开，标记作废）。
- 删除确认只来自一次全新会话的证据：有 UIDL 时看 UIDL 列表是否还包含该 UIDL；无 UIDL 时逐封完整 RETR 取 SHA-256 摘要比对。
- 无 UIDL 邮箱的身份仅由完整原件摘要确认，主题、日期、Message-ID 都不作为合并依据；摘要相同的多封来信记录为同一凭据的重复实例，并显式保留无法区分的局限说明。
- 本地没有完整原件凭据的邮件永远不会被 DELE；清理不需要通过“再清空一次邮箱”消除疑问。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。台账 `ledger/state.json` 与原件并列，所有写入经临时文件、fsync 与原子改名；状态只能由带证据的事件推进，并保留完整历史链供换班复核。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。
